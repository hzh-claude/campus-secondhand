# 校园二手交易小程序

一个面向高校的校内二手交易平台，跑在 **微信小程序 + 微信云开发** 上。

发布、下单、校内配送、聊天、收藏、意见反馈、隐私说明——整套流程是通的，不是演示壳子。

> 这是从零写的一个完整项目，**没有使用任何 UI 模板**（只用了 Vant Weapp 组件库）。
> 代码注释写的是「为什么这么做」，而不是「这行在干什么」。

---

## 功能

| 模块 | 内容 |
|---|---|
| 商品 | 发布 / 编辑 / 下架 / 删除 / 分类（4 类）/ 搜索 / 收藏 / 多图上传 |
| 交易 | 下单 → 卖家确认 → 校内配送或自提 → 完成 / 取消，超时自动关闭 |
| 配送 | 配送员白名单、配送大厅抢单、按楼层与距离计算配送费 |
| 社交 | 站内聊天（含图片消息）、站内通知、微信订阅消息提醒 |
| 用户 | 注册核验（学号 + 校内模糊定位）、编辑资料、收货地址 |
| 运营 | 意见反馈（含截图，走微信内容安全检测）、隐私说明、设置 |

**没有在线支付**：交易全部线下完成，所以不需要微信支付商户号。这是刻意的——校园二手交易的真实场景就是当面验货付款，加支付会引入退款、分账、商户号一整套东西，收益却很小。

## 技术栈

| 层 | 用什么 |
|---|---|
| 前端 | 微信小程序原生（WXML / WXSS / JS）+ Vant Weapp 1.11 |
| 后端 | 微信云开发：10 个云函数 + 云数据库 + 云存储 |
| 身份 | 云函数里的 `cloud.getWXContext().OPENID`，**不用 `wx.login`、不存 token、本地无登录态** |

### 三条设计原则

**1. 云函数是唯一的裁决者。**
前端所有「按钮藏起来」「这里不让点」都只是显示。真正的判断（是否注册、是否配送员、是不是你自己的东西）全在云函数里。

**2. 客户端零数据库直连。**
24 个页面里没有一处 `wx.cloud.database()`。所有读写都走云函数，所以 9 个集合的权限可以**全部设成「所有用户不可读写」**——直接断掉「前端绕过校验改数据」这条路。

**3. 云函数 require 不到 `utils/`。**
云函数独立打包，只能读自己目录。所以有些常量天然会有两份（比如园区名、订阅消息字段）。这些地方都留了 `搜索 XXX 能同时找到这两处` 的注释——这是已知分叉，不是疏忽。

## 快速开始

### 0. 前置

- 微信开发者工具（稳定版）
- 一个已开通**云开发**的小程序 AppID
- 不需要后端服务器，不需要域名，不需要备案就能在开发者工具里跑起来

### 1. 拉代码

```bash
git clone https://github.com/YOUR_NAME/YOUR_REPO.git
```

### 2. 导入

微信开发者工具 → 导入项目 → 选这个目录。

导入时会提示填 AppID（`project.config.json` 里是空的，故意的）。

### 3. 填配置

打开 `utils/cloud-config.js`：

```js
const ENV_ID = 'YOUR_ENV_ID';              // ← 改成你的云开发环境 ID
const SERVICE_EMAIL = 'your-email@example.com';
```

环境 ID 在：云开发控制台 → 设置 → 环境设置。

### 4. 部署后端

在开发者工具里，右键 `cloudfunctions` 下的**每一个**函数目录 →「**上传并部署：云端安装依赖**」。

10 个函数都要传，少一个对应功能就报「云函数不存在」。

### 5. 建数据库

云开发控制台 → 数据库 → 手动创建 9 个集合（名称必须完全一致）：

```
goods  users  address  favorites  orders  notifications  feedback  conversations  messages
```

**权限全部选「所有用户不可读写」。** 所有读写都经过云函数（管理员身份运行，不受这个限制）。

### 6. 编译运行

## 后端细节

### 10 个云函数

| 云函数 | 负责 | `config.json` 声明的权限 |
|---|---|---|
| `login` | 首次打开时建档案 | — |
| `user` | 注册核验、编辑资料、卖家主页 | — |
| `publishGoods` | 发布 / 编辑商品 | `security.msgSecCheck` |
| `manageGoods` | 下架 / 删除 / 我的商品 | `security.msgSecCheck` |
| `favorite` | 收藏 | — |
| `order` | 下单、接单、配送、订阅消息、超时关闭 | `subscribeMessage.send` + 定时触发器 |
| `chat` | 会话与消息 | `security.msgSecCheck`、`security.imgSecCheck` |
| `notice` | 站内通知 | — |
| `feedback` | 意见反馈 | `security.msgSecCheck`、`security.imgSecCheck` |
| `address` | 收货地址 | — |

`config.json` 里的 `permissions.openapi` **不要删**。云调用必须点名声明接口，否则返回 `-604101 no permission`。这个权限有约 10 分钟缓存，刚部署完报错是正常的。

### 定时触发器

`cloudfunctions/order/config.json` 已经写好每小时关闭超时订单：

```json
{ "name": "autoCloseExpiredOrders", "type": "timer", "config": "0 0 * * * * *" }
```

**部署函数不会自动上传触发器**，要单独右键 `cloudfunctions/order` →「上传触发器」。

### 云存储

四个前缀由代码约定，不要改：

```
goods/<openid>/...        商品图
avatar/<openid>/...       头像
chat/<openid>/...         聊天图片
feedback/<openid>/...     反馈截图
```

中间那层 `openid` 是**安全边界**：服务端删除文件时会用调用者的 openid 重算前缀，只删自己目录下的文件。只按 `goods/` 判断的话，拿到别人的 fileID 就能让服务端删掉别人的图。

### 订阅消息

两个模板的字段是固定的，选模板时要挑字段名对得上的：

| 用途 | 字段 |
|---|---|
| 新订单通知 | `thing7` 商品名称、`thing19` 用户名称、`date6` 下单时间、`character_string2` 订单编号 |
| 订单状态通知 | `thing9` 订单标题、`phrase3` 订单状态 |

找不到字段完全一致的模板，就改代码里的字段名（`cloudfunctions/order/index.js:512-515`、`541-542`）。

两个必然踩的坑：

- `phrase` 类型要求「5 个以内纯汉字」，写成 `已完成!` 整条被拒（`47003`）。
- 订阅消息是**一次授权一条**，发完就 `43101`。项目里用**站内通知**兜底，不要试图做「永久订阅」——个人主体没有长期订阅。

## ⚠️ 上线前必读：服务类目

**这一节比代码重要。** 功能写对了但类目过不了，一样上不了线。

微信小程序的**服务类目由主体类型决定**，不由代码决定：

| 主体 | 能做的事 | 这个项目 |
|---|---|---|
| 个人 | 类目极少，**没有二手交易 / 电商类目** | ❌ 提审会被驳回（"涉及电商模式"） |
| 企业 | 「商家自营」等 | ⚠️ 只覆盖自营，不是 C2C |
| 企业 + 增值电信资质 | 「电商平台」 | ✅ 这才是它真正的形态 |

用户发布、用户购买 = **C2C**，落在「电商平台」这一档，通常需要 **《增值电信业务经营许可证》（EDI）**：内资公司、注册资本 ≥ 100 万、3 人社保、审批 45–60 个工作日。

**所以请先做这一步，再动代码：**

1. 微信公众平台 → 设置 → 基本设置 → **服务类目** → 看看你的主体实际能选到什么。
2. 「添加类目」里搜不到对应项（显示"暂无匹配类目"）时，就是类目关过不去。
3. 类目名称以**你后台实际显示的可选项**为准，上面那张表是分类逻辑，不是可选项清单。

> 代码是通用的，类目是主体相关的。

另外两条同样会卡住上线的东西，写在 [`docs/上线踩坑记录.md`](docs/上线踩坑记录.md)：

- **《用户隐私保护指引》**：位置、相册/摄像头、**剪切板**、**选中的文件** 都要声明。指引不完整时微信会回收已开通的隐私接口权限，表现是「本地好的、线上报 `api scope is not declared`」。
- **外链图片**：`<image src="https://...">` 走 `downloadFile`，域名必须在白名单里，而白名单要求域名完成 ICP 备案。开发者工具默认不校验域名，工具里看不出任何问题，线上是**一片空白**。

## 常见故障

| 现象 | 真实原因 | 怎么办 |
|---|---|---|
| 云调用全部失败 `env not exists` | `ENV_ID` 没改 | 改成你的环境 ID |
| 「云函数不存在」 | 那个函数没部署 | 右键该目录上传并部署 |
| 改了代码没生效 | 没重新部署云函数 | 重新部署，看 `CODE_VERSION` |
| 所有人都注册失败"不在校内" | 坐标抄反 / 坐标系不对 / 半径太小 | 看云函数日志里的 `距离=` |
| 开发者工具里定位必然失败 | 模拟器不支持 `getFuzzyLocation` | 用真机预览测 |
| `api scope is not declared` | 隐私指引没声明这个接口 | 后台补指引 |
| `-604101 no permission` | `config.json` 缺接口声明，或刚部署 | 检查 config，等 10 分钟 |
| 订阅消息 `40037` | 模板 ID 抄错（注意 `I`/`l`/`1` 同形） | 重新复制 |
| 订阅消息 `43101` | 授权额度用完了 | 让用户重新点「开启通知」 |
| 配送员看不到单 | `DEFAULT_ADMIN_OPENIDS` 空着或填错（**填错不报错**） | 调 `{"action":"whoami"}` 看 `adminCount` |
| 图片空白、无报错 | 用了外链图片 | 换本地图或云存储 `cloud://` |
| Vant 组件不显示 | `miniprogram_npm/` 缺失 | `npm install` → 工具 → 构建 npm |

## 已知限制

这些是**有意为之**或**尚未完成**的：

1. **没有在线支付**，交易全线下完成。
2. **定位核验挡不住存心伪造的人。** 客户端上报的经纬度无法证明。真正的门槛是「学号唯一 + 真实姓名」，定位只是挡掉明显外地人的粗筛。`getFuzzyLocation` 不调 GPS，误差是**公里级**——别把它当围墙。
3. **配送员白名单在源码 / 环境变量里**，没有管理员后台页面。轮换改环境变量 `ADMIN_OPENIDS` 即可，改完即生效不用重新部署。
4. **订阅消息是一次性的**，靠站内通知兜底。
5. **搜索是本机历史 + 云端前缀匹配**，没有分词和排序权重。
6. **图片压缩在客户端做**（反馈图上限 900KB），没有服务端转码。
