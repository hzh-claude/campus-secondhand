# 上线踩坑记录

这份文档记的不是"代码怎么写"，而是**代码全写对了之后，为什么还是上不了线**。

这个项目在开发完成后实际提交过一次审核，被驳回了。驳回理由不在代码里，在主体资质里。下面按"会卡住你的顺序"排列。

---

## 一、最硬的一关：服务类目

### 被驳回的原话（大意）

> 存在个人主体小程序未开放的服务类目 / 涉及电商模式

### 为什么会这样

微信小程序的**服务类目由主体类型决定**，不由代码决定：

| 主体 | 可选类目 | 能覆盖"用户之间交易"吗 |
|---|---|---|
| 个人 | 极少，没有电商 / 二手交易 | ❌ |
| 企业 | 「商家自营」等 | ⚠️ 只覆盖"自己卖自己的货" |
| 企业 + 增值电信资质 | 「电商平台」 | ✅ |

一个**用户发布商品、其他用户购买**的平台，是 **C2C**，不是"商家自营"。按微信的分类它落在「电商平台」这一档。

而「电商平台」类目需要 **《增值电信业务经营许可证》（EDI）**：

- 内资公司
- 注册资本 ≥ 100 万
- 3 人以上社保
- 审批约 45–60 个工作日

### 所以先做这一步

打开微信公众平台 → 设置 → 基本设置 → **服务类目**，看看你的主体**实际**能选到什么。

「添加类目」里搜不到对应项（显示"暂无匹配类目"）时，就是类目关过不去 —— 这时候继续改代码没有任何意义。

### 三条路径（按代价排序）

| 路径 | 代价 | 说明 |
|---|---|---|
| 换一个企业主体的小程序 | 重新注册 AppID | 最干净。但注意：小程序**名称全局唯一**，旧账号占着的名字新账号用不了，得先改名或注销 |
| 个人 → 企业 主体变更 | 公证书约 300 元，1–7 个工作日 | **AppID 会保留**，代码不用动。个人→企业属于跨类型变更，必须公证 |
| 去办 EDI | 注册资本 100 万 + 3 人社保 + 45–60 工作日 | 只适合真的要做大的人 |

> ⚠️ **注册资本 1 万的小微企业也过不了 EDI 这一关。** "有营业执照"和"有电商平台资质"是两件事，别混。

## 二、隐私保护指引：不是填个表就完了

### 1. 指引"审核通过"≠"接口生效"

更糟的是：**指引不完整时，微信会回收你已经开通的隐私接口权限。**

典型表现是「本地好好的，线上报错」：

```
setClipboardData:fail api scope is not declared in the privacy agreement
```

### 2. 哪些东西要声明（这个项目踩到的）

| 能力 | 代码里的调用 | 备注 |
|---|---|---|
| 位置信息 | `wx.getFuzzyLocation` | `app.json` 的 `requiredPrivateInfos` 要同时声明 |
| 相册 / 摄像头 | `wx.chooseMedia` | |
| 剪切板 | `wx.setClipboardData` | **最容易漏**：「复制邮箱」「复制 openid」都算 |
| 选中的文件 | `wx.chooseMessageFile` | 见下 |

### 3. 剪切板这一条藏得很深

复制客服邮箱、复制自己的 openid，都是很普通的交互，但 `wx.setClipboardData` 是隐私接口 —— 不在指引里声明，**点了就是失败**。

而这条通常是在**上线当天的真机上**才发现的，因为开发者工具对隐私接口的校验比真机松。

### 4. 「选中的文件」这一条可能删不掉

这个项目只让用户选图片，用的是 Vant 的 `van-uploader`。但：

```
miniprogram_npm/@vant/weapp/uploader/utils.js:107  →  wx.chooseMessageFile
```

**组件内部调了 `wx.chooseMessageFile`**，所以后台指引里必须声明「选中的文件」。这一项通常**没有删除按钮**（只有用户自己添加的项才有 ⊖），只能如实填写。

> 结论：不要以为"我只用了选图，所以只需要相册"。第三方组件的内部调用也算你的调用。

### 5. 指引里承诺的联系方式，必须在小程序里找得到

指引第 4 节填了一个邮箱，审核会拿它和**小程序里实际展示的联系方式**对照："你说能通过这个邮箱联系，但小程序里没有。"

这个项目为此专门在「隐私说明」页加了客服邮箱（`pages/privacy/privacy.wxml` 第七节），值来自 `utils/cloud-config.js` 的 `SERVICE_EMAIL` —— **一处定义，两处使用**。

### 6. 发布前还有一道：备案

小程序**发布**前需要完成 ICP 备案（在微信公众平台里走流程）。这个和"审核通过"是两件事，不要以为提审过了就能上线。

## 三、订阅消息：四个一次性的坑

1. **云调用要在 `config.json` 里点名声明**
   ```json
   { "permissions": { "openapi": ["subscribeMessage.send"] } }
   ```
   不声明直接返回 `-604101 no permission`。而且权限有约 10 分钟缓存，刚部署完报错是正常的。

2. **一次授权只能发一条**
   用户点一次「开启通知」攒 1 条额度，发完就返回 `43101`。所以：
   - 个人主体**没有**"长期订阅"，"永久开启"不存在；
   - 本项目的做法是**站内通知兜底**：写数据库，用户进小程序就能看到。

3. **超长不是截断，是整条被拒**
   `thing` 类型 20 字符、`phrase` 5 个以内**纯汉字**。超了返回 `47003`，整条都发不出去。代码里用 `clip()` 先截。

4. **横条收起后必须留续期入口**
   通知横条曾经放在「我卖出的 / 我买到的」页面顶部，为了不打扰改成了"开过一次就收起"。收起之后，**设置页就是唯一的入口** —— 所以那里不能藏。

## 四、定位：误差是公里级，不是米级

### 1. `getFuzzyLocation` 不调 GPS

它用的是**基站 + WiFi + IP** 的网络定位，微信还会再做一层模糊化偏移。误差是**几百米到几公里**，郊区基站稀就更差。

所以拿它做"是否在校内"的判定，半径设成几百米等于抛硬币：

- 设小了 → 真学生经常被误伤
- 设大了 → 根本不是校内的人也能过

本项目的最终值是 **4000 米**，并明确承认：**它挡不住存心伪造的人，也证明不了学生身份。** 真正把关的是「学号唯一 + 真实姓名」。

### 2. `type` 默认是 `wgs84`，和国内地图差约 650 米

```js
wx.getFuzzyLocation({ type: 'gcj02', ... })  // 必须显式传
```

不传的话默认 `wgs84`，而你从腾讯位置服务拾取器拿到的坐标是 `gcj02` —— 两者差约 650 米。这 650 米会**白白吃掉你的半径余量**。

### 3. 模拟器里必然失败，而且报错和"后台没开通"一模一样

开发者工具不支持 `getFuzzyLocation`。所以：

- 定位功能**只能用真机测**；
- 模拟器里那个 `no permission` 报错**不能**作为"后台没开通"的证据。

### 4. 不要把距离显示给用户

正常时是噪音，异常时制造误报。日志里打就够了。

## 五、外链图片：一个看不见的坑

```html
<image src="https://images.unsplash.com/..."></image>
```

小程序里加载网络图同样走 `downloadFile`，域名必须在后台「downloadFile 合法域名」里。而**添加合法域名要求域名已完成 ICP 备案** —— 所以 `images.unsplash.com` 这类图床**永远加不进去**。

最要命的是：

> **开发者工具默认不校验域名**（`project.private.config.json` 里的 `urlCheck` 为 `true` 时才会校验，而默认关）。

表现是**三个空白框，没有任何报错**。首页是每个用户第一眼看到的地方。

**结论**：图片一律放本地 `images/` 或上传到云存储（`cloud://` 开头的 fileID 不受域名限制）。想换成推广图，就把首页的 CSS 渐变块换成 `cloud://` 图片。

## 六、云函数：部署这件事没有任何提示

1. **改完必须手动重新部署那一个云函数。** 开发者工具不会自动上传，界面也不提示。表现是"我明明改了，线上还是老行为"。
2. **云函数之间 `require` 不到 `utils/`。** 每个云函数独立打包，只能读自己目录。所以常量会有两份，靠注释里的「搜索 XXX 能同时找到这两处」维系。
3. **部署函数 ≠ 上传触发器。** 定时触发器要单独右键「上传触发器」。
4. **`CODE_VERSION` 是唯一可靠的探针。** 每个函数顶部都有一个，改完 +1，然后调一个动作看云端返回的版本号 —— 比对着日志猜快得多。

## 七、提审前最后一张自查表

- [ ] 服务类目能覆盖"用户之间交易"（第二节）
- [ ] 隐私保护指引已通过，且包含位置 / 相册 / 摄像头 / 剪切板 / 选中的文件
- [ ] 指引里承诺的联系方式，小程序里点得到（`pages/privacy`）
- [ ] 小程序名称：注册名 = `app.json` 的 `navigationBarTitleText` = 「关于」页显示的名字
- [ ] 页面里没有开发期遗留：调试开关、`DEV_SKIP_LOCATION`、测试账号、假数据
- [ ] 后端没有写死开发者的 openid（配送员白名单）
- [ ] 已配置体验版，并提交了测试账号 / 审核备注（说明"注册需要校内定位，请在体验版测试"）
- [ ] ICP 备案已完成
- [ ] 真机上把第六节的验收清单走了一遍

## 八、一句话总结

> **这个项目里最难的部分从来不是代码，是"你是谁"这件事。**
>
> 同一个功能，个人主体做不了，企业主体要资质，有资质的公司还得等 45–60 天。
> 先确认主体能拿到什么类目，再决定要不要投入开发 —— 顺序反了，代码写得再对也没用。
